# project-init

Проект создан из boilerplate. Проведи пользователя по полям [`docs/project.md`](../../../docs/project.md) и заполни паспорт. Общайся по-русски.

Паспорт — **внешние** ресурсы (Figma, Planfix, домены, Rollbar). То, что видно в репо (Storybook, CMS/бэкенд в коде), в паспорт не пиши и не спрашивай.

## Шаги

1. **Прочитай паспорт.** Запомни, какие поля уже заполнены, какие пусты, какие `нет`.
2. **Собери то, что видно из репозитория**, и покажи пользователю на подтверждение:
    - репозиторий фронтенда — `git remote get-url origin`, без логина и токена в URL;
    - репозиторий бэкенда — по умолчанию тот же `origin` (монорепо). Спроси только если пользователь явно говорит, что бэкенд в другом репо, или что бэкенда нет (`нет`);
    - окружения — ветки и правила деплоя из `.gitlab-ci.yml` и `ci/`.
3. **Пройди разделы по одному**, в порядке паспорта: Общее → Figma → Planfix → Окружения и домены → Rollbar. Один раздел — одно сообщение со списком его пустых полей. Ответы пользователя:
    - значение — записать;
    - `нет` — сервис не используется, записать `нет`;
    - `позже` или пропуск — оставить ячейку пустой.
4. **Нормализуй ответы:**
    - Figma: из URL `figma.com/design/<fileKey>/…` (или `/file/`, или `/proto/`) возьми `fileKey`. Для страниц из URL с `node-id=123-456` запиши `123:456`. Строки ролей не удаляй и не переименовывай. Файл прототипов пуст — оставь пустым, если прототипы в том же файле;
    - Planfix: ссылку на паспорт спрашивай у пользователя. **Проект (id)** — сам возьми из MCP `get_projects`: найди проект по названию из паспорта (или близкому). Нашёл — запиши id, пользователю покажи для подтверждения, не спрашивай «какой id». Не нашёл или MCP недоступен — тогда спроси id. В проверке MCP (шаг 7) используй уже записанный id;
    - Rollbar: имя в `.rollbar-mcp.json` — короткое (`frontend`, `backend`), ссылка на проект в UI, `environment` — как сайт шлёт его в Rollbar (`production`, `staging`). Токен в паспорт не писать: допиши проект в `.rollbar-mcp.json` (скопируй образец, если файла нет) и попроси токен scope `read` отдельно. Бэкенда нет — строка бэкенда `нет`, ключ `backend` из конфига убери.
5. **Отсей секреты.** В паспорт идут только ссылки и идентификаторы. Ответ похож на токен, пароль или ключ (`figd_…`, `glpat-…`, `Bearer …`, длинная случайная строка вне URL) — не записывай его. Токен Rollbar живёт в `.rollbar-mcp.json`, токен Figma — в `FIGMA_API_KEY`. Дай ссылку на [`docs/mcp.md`](../../../docs/mcp.md).
6. **Запиши паспорт**, сохраняя структуру таблиц: одно значение — одна ячейка. Роли страниц Figma и строки Rollbar не удаляй.
7. **Проверь MCP.** Для каждого заполненного внешнего сервиса одно чтение по id из паспорта. Сервер не подключён или просит авторизацию — запиши это в отчёт со ссылкой на `docs/mcp.md`.
    - Figma: `get_figma_data` по `fileKey` и `node-id` страницы UI Set;
    - Planfix: задача или проект по id;
    - Rollbar: `list-projects` или `list-items` с `project` = имя из паспорта. Файла `.rollbar-mcp.json` нет — не вызывай сервер, напиши, что его нужно создать из образца.
8. **Проверь секреты:** `gitleaks dir --redact --no-banner docs/project.md .rollbar-mcp.example.json`, если `gitleaks` есть в `PATH`. Находка на идентификаторе (не секрете) — узкий allowlist по правилам раздела Secrets в `AGENTS.md`. `.rollbar-mcp.json` в коммит не предлагай.

## Готово, когда

- каждое поле паспорта заполнено, равно `нет` или явно отложено пользователем;
- в отчёте: заполненные разделы, отложенные поля, статус MCP по каждому сервису, результат gitleaks;
- в паспорте нет ни одного токена.

Коммит — только по просьбе пользователя, сообщение по скиллу `commit-message`.

# Паспорт проекта

Заполняется при старте проекта из boilerplate скиллом `/project-init` (`.cursor/skills/project-init/SKILL.md`).

Значения ячеек:

- пусто — ещё не заполнено, агент спрашивает;
- `нет` — сервис или поле в проекте не используется.

Паспорт — внешние ресурсы (Figma, Planfix, домены, Rollbar). То, что видно в репо, сюда не пишется. Только ссылки и идентификаторы; токены — в окружении и в `.rollbar-mcp.json`, см. [`mcp.md`](mcp.md).

## Figma

Один файл макета на проект. Роли страниц одинаковы на всех проектах: агент открывает страницу по `node-id` из таблицы, а не ищет холст по названию.

| Поле       | Значение |
| ---------- | -------- |
| Файл (URL) |          |
| fileKey    |          |

В ссылке `node-id=123-456`, в MCP — `123:456`.

| Роль                    | node-id |
| ----------------------- | ------- |
| UI Set                  |         |
| Макеты страниц          |         |
| Функциональное описание |         |
| Примеры анимаций        |         |

Прототип иногда лежит в другом файле. Пусто или `нет` — прототипы в том же файле, на странице «Примеры анимаций».

| Поле                  | Значение |
| --------------------- | -------- |
| Файл прототипов (URL) |          |
| fileKey прототипов    |          |

### Как читать файл

**UI Set.** Две зоны: UI-элементы (компоненты: кнопки, поля, шапка, подвал, форма, иконки) и технические компоненты страниц. Отдельные секции: 404, cookie, open graph / favicon / web clip, юридическая текстовая, типографика. Кадры типографики и служебных экранов названы шириной макета.

**Макеты страниц.** Секция = страница сайта. Экран — фрейм `{страница} {ширина}`. Типичные ширины: 375, 768, 1440, 1920, 2500; фактические — имена фреймов в файле. Рядом с экраном состояния (hover) и текстовые пометки. Пометка — часть спецификации. Ссылка из пометки ведёт на прототип: `page-id` — страница примеров анимаций, `fileKey` может быть другим.

**Функциональное описание.** Кадр на страницу сайта. В режиме презентации там видео; текст кадра — поведение анимации.

**Примеры анимаций.** Секция = один сценарий. Кадры внутри — шаги прототипа слева направо.

Страницы файла вне этой таблицы (превью всех ширин, ресёрч, архив по датам) не читать, пока задача прямо на них не ссылается.

Задача на страницу: секция в «Макетах страниц» + одноимённый кадр в «Функциональном описании» + сценарий в «Примерах анимаций», если пометка или описание на него ссылается. Компонент брать из UI Set. Пропсы уже существующего компонента — из Storybook MCP, не снимать с экрана страницы.

## Rollbar

Ошибки и деплои. Токены только в `.rollbar-mcp.json` (gitignore). Образец — [`.rollbar-mcp.example.json`](../.rollbar-mcp.example.json).

В инструменты MCP (`list-items`, `get-top-items`, `get-item-details`, `list-occurrences`, `get-deployments`, `get-version`) параметр `project` — это `projects[].name` из конфига, не slug из URL. `environment` по умолчанию `production`; для stage и dev бери имя из таблицы. Номер item (counter) в паспорт не пишется: он в ссылке на item.

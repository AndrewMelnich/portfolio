# Commit message

Сгенерируй текст git commit message по **текущей chat-сессии** и фактическому diff.

**Не** создавай commit. **Не** делай `git add` / `git commit` / `git push`. Только сообщение.

## Источник сообщения

1. **Why** — из этой сессии: задача юзера, итог фиксов/фич, зачем изменение.
2. **What** — сверь с `git status` / `git diff` (staged + unstaged). Сообщение должно отражать реальный diff, не только рассказ в чате.
3. Если чат и diff расходятся — коротко отметь расхождение и предложи вариант под diff (или спроси, что учитывать).

## Стиль сообщения

- Как в недавних коммитах репо (`git log -10 --oneline`): краткий subject, focus на **why**, не список файлов.
- 1–2 предложения. Без Conventional Commits-префиксов, если репо их не использует.
- Язык subject — как в истории репо (обычно EN).

## Протокол

1. Параллельно (read-only): `git status`, `git diff` (+ `--staged`), `git log -10 --oneline`.
2. Составь message.
3. В ответе **обязательно** выведи **только текст message** внутри fenced code block (plain text), чтобы у юзера была кнопка **Copy**:

````markdown
```
Subject line here.

Optional second sentence if needed.
```
````

До/после блока — максимум одна короткая строка (какие файлы учтены), без лишнего.
